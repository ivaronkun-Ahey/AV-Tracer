# ⚡ AV-Tracer — симулятор аудио-видео систем

**Как Cisco Packet Tracer, только для аудио-видео оборудования.**

Собирайте схемы AV-систем мышкой: перетащите устройства на холст, соедините их
кабелями, настройте параметры и запустите проверку сигнала — без дорогого «железа».

> Интерфейс на русском языке. Названия моделей оборудования (Shure SM58 и т. п.)
> и обозначения разъёмов (XLR, HDMI, SDI) оставлены международными.

---

## 🚀 Запуск

### Вариант 1. Docker — одна команда (рекомендуется)

```bash
docker compose up
```

Откройте в браузере **http://localhost:3000**. Готово.

### Вариант 2. Скрипт запуска (Linux / macOS)

```bash
./run.sh
```

Скрипт сам создаст окружение Python, поставит зависимости и поднимет backend
(порт 8000) и frontend (порт 3000).

### Вариант 3. Вручную (два терминала)

**Backend (порт 8000):**
```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

**Frontend (порт 3000):**
```bash
cd frontend
npm install
npm run dev
```

Адреса: интерфейс — http://localhost:3000, API — http://localhost:8000,
документация API — http://localhost:8000/docs.

> **Backend не обязателен.** Симуляция целиком считается в браузере, поэтому
> достаточно запустить только frontend (`cd frontend && npm install && npm run dev`).
> Python-сервер сейчас — заготовка для будущих функций (хранение проектов,
> учётные записи, ИИ-ассистент).

## 🎬 Как пользоваться

1. **Добавьте устройства** — перетащите карточку из библиотеки слева на холст.
   Не знаете, с чего начать? Откройте меню **«Примеры»**.
2. **Соедините** — схема читается слева направо: **входы — на левой кромке**
   устройства, **выходы — на правой**, у каждого порта подпись. Кликните по
   выходу одного устройства, затем по входу другого. Совместимые свободные
   входы подсвечиваются зелёным; несовместимые сигналы и занятые входы
   соединить нельзя. Ethernet-порт встаёт на ту сторону, куда идёт его кабель.
   Каждый кабель получает маркировку (A-001 — аудио, S — акустика, V — видео,
   N — сеть, D — Dante), устройства — обозначения (MIC-01, AMP-01…).
3. **Упорядочьте** — кнопка **«Упорядочить»** расставляет устройства по ходу
   сигнала: источники слева, приёмники справа, с минимумом пересечений
   (одним шагом, отменяется `Ctrl+Z`). Кабели прокладываются под прямыми углами.
3. **Настройте** — выберите устройство, измените его параметры в панели справа
   (усиление, фантомное питание, разрешение и т. д.).
4. **Проверьте** — нажмите **«Симуляция»**: внизу откроется панель с цепочками
   сигнала, ошибками и предупреждениями. Кликните по проблеме — устройство
   выделится на холсте.
5. **Сохраните** — кнопка «Сохранить» выгружает проект в JSON, «Открыть» —
   загружает обратно. Файл проверяется: формат, уникальность идентификаторов,
   размер (до 5 МБ, до 2000 устройств). В файле записана версия формата
   (`schemaVersion`); проекты старых версий обновляются автоматически, и
   приложение сообщает, что изменилось. Схема также автоматически сохраняется
   в браузере. Обозначения устройств (MIC-01…) постоянные и редактируются в
   панели свойств; номера не сдвигаются при удалении других устройств.
6. **Выпустите документацию** — меню **«Экспорт»**: схема в PNG (светлая тема),
   документ для печати / PDF (схема со штампом, спецификация оборудования,
   кабельный журнал с итогами по типам кабеля), отдельно спецификация и
   кабельный журнал в CSV для Excel.

### Горячие клавиши и управление

| Действие | Как |
|---|---|
| Удалить выбранное устройство/кабель | `Delete` или `Backspace` |
| Отменить соединение / снять выделение | `Esc` |
| Отменить / повторить действие | `Ctrl+Z` / `Ctrl+Shift+Z` |
| Масштаб | колесо мыши |
| Панорама холста | перетаскивание пустого места |
| Вписать схему в экран / сбросить вид (100 %) | кнопки в правом нижнем углу |
| Привязка к сетке, подписи кабелей | меню «Вид» |

## 📚 Библиотека оборудования (60 устройств)

- **Аудио:** микрофоны (Shure, AKG, Sennheiser, Rode), радиосистемы (Shure
  ULXD4, Sennheiser EW-DX), микшеры (Allen & Heath, Yamaha, Behringer, Midas),
  усилители (Crown, QSC, Lab Gruppen), акустические системы и сабвуферы (JBL,
  EV, QSC, RCF, Yorkville), DI-боксы и аудиоинтерфейсы (Radial, Focusrite),
  процессоры/DSP (QSC, Biamp), сетевое аудио Dante.
- **Видео:** камеры (Sony, Panasonic, PTZOptics, Canon), дисплеи, LED-экраны и
  проекторы (Samsung, LG, Absen, Epson, Barco, Christie), коммутаторы, матрицы
  и масштабаторы (Extron, Lightware, Blackmagic, Roland, Kramer), медиаплееры
  (BrightSign, Apple TV), AV-over-IP кодеры/декодеры (Crestron NVX, Extron NAV),
  запись и стриминг (Blackmagic HyperDeck, Teradek).
- **Сеть и управление:** коммутаторы (Cisco, Netgear, Aruba), контроллеры
  (Crestron, Extron, AMX), точки доступа Wi-Fi (Ubiquiti), сенсорные панели.

Каталог хранится в `frontend/src/data/catalog.json` и проверяется схемой при
загрузке и в тестах. Порты задаются короткой записью: тип разъёма, направление
и сигнал определяются по префиксу идентификатора (`xlr_in`, `hdmi_out`,
`dante_out`, `eth`…), а `"xlr_in*16"` означает 16 входов `xlr_in_1…xlr_in_16`.

Симуляция проверяет схему:

- **сигнал от источника до приёмника по портам**: колонка или дисплей,
  подключённые кабелем, но без достижимого источника, получают ошибку «нет
  сигнала» с подсказкой, где он теряется;
- **прохождение через устройство**: усилитель передаёт сигнал в тот же канал
  (вход L → выход L), презентационный коммутатор — только выбранный вход,
  матрица — по таблице «вход>выход»; Ethernet-порт оконечного устройства —
  управление, через него видео и звук не идут;
- **все ветви сигнала** — по каждому кабелю с выхода (стерео L/R, параллельные
  АС), аудио не «утекает» в видеоустройства через общий сетевой коммутатор;
- **уровни сигнала** в дБu: чувствительность микрофона, аттенюатор, усиление
  входа и общий уровень микшера/DSP; норма на входе усилителя или активной АС —
  от −10 до +20 дБu, иначе предупреждение «слабый сигнал» или «перегрузка»;
- **разрешение видео**: сигнал выше возможностей коммутатора/кодера
  (например, 4K в ATEM Mini Pro) и выше родного разрешения дисплея/проектора;
- совместимость сигналов и **занятые порты** (в один вход — один кабель);
- активные/пассивные АС относительно усилителя, **бюджет мощности
  усилитель↔АС** (мощность и сопротивление с учётом параллельного включения);
- **фантомное питание** — его подаёт вход микшера/интерфейса, к которому
  подключён конденсаторный микрофон (общий переключатель +48V или по каналу);
- **длину кабелей** и питание PoE.

Ограничения модели: не проверяются пропускная способность сети, совместимость
кодеков, подписки и тактирование Dante, HDCP/EDID, частота кадров, детальная
электрика и акустика. Пределы длины кабелей и уровни сигнала — упрощённые оценки.

Клик по кабелю открывает **инспектор соединения**: тип сигнала, разъём,
описание и редактируемая длина с проверкой допустимого максимума.

## 🧩 Структура проекта

```
AV-Tracer/
├── frontend/              # Интерфейс: React + TypeScript + Vite + Konva + MUI
│   └── src/
│       ├── components/    # Холст, узлы, кабели, панели
│       ├── features/      # Redux-состояние (canvasSlice)
│       ├── sim/           # Браузерный движок симуляции (+ тесты)
│       ├── data/          # Библиотека оборудования, примеры, подписи
│       └── types/         # Типы TypeScript
├── backend/               # Заготовка API: FastAPI + Python (/health)
│   ├── app/main.py
│   └── tests/             # Проверка, что API поднимается (pytest)
├── shared/sim-fixtures/   # Эталонные схемы для регрессионных тестов движка
├── archive/               # Устаревшие файлы (прежний Python-движок) — см. archive/README.md
├── docker-compose.yml     # Запуск всего одной командой
├── run.sh                 # Запуск без Docker
└── docs/                  # Подробная документация и архив
```

## 🛠 Технологии

**Frontend:** React 18, TypeScript, Vite, Redux Toolkit, Konva.js, Material-UI, ELK (автораскладка), zod.
**Backend:** FastAPI, Pydantic, Uvicorn.

## 🧪 Тесты и проверки

```bash
cd frontend
npm test                    # тесты движка, состояния и эталонов (Vitest)
npm run lint                # ESLint
npm run typecheck           # TypeScript
npm run icons:generate      # пересобрать пиктограммы устройств (src/components/deviceIcons.ts)

cd backend
pip install -r requirements-dev.txt
pytest                      # заготовка API поднимается и отвечает
```

Движок симуляции один — `frontend/src/sim/engine.ts`, он работает в браузере.
Если понадобится проверка на сервере (оценки в учебном режиме, ИИ-ассистент,
внешний API), этот же модуль запускается в Node, а не переписывается на другом
языке. Регрессию ловят эталонные схемы `shared/sim-fixtures/*.json`: результат
симуляции сверяется с полем `expected`. После намеренного изменения логики
обновите эталоны (`npm run fixtures:update` во `frontend`) и проверьте разницу в git.
