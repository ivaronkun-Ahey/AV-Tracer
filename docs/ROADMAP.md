# AV-Tracer — план работ

Обновлено: 29 октября 2026. Текущее состояние — `docs/STATUS.md`.
Решения владельца: чертежи по ГОСТ СПДС, сначала PDF, помещения — рамками
на холсте с фильтром, порядок «помещения → чертежи → учебный режим».

## 1. Помещения (зоны) — сделано

- В проекте — список помещений («Аппаратная», «Зал», «Переговорная»), у
  устройства — поле «помещение». Формат файла: `schemaVersion` 3 (`rooms`,
  `device.room`), старые проекты открываются без изменений.
- На холсте помещение — рамка с подписью вокруг своих устройств; рамку можно
  перетащить вместе с устройствами. Автораскладка расставляет устройства
  внутри рамок.
- Фильтр «показать одно помещение»: кабели в другие помещения обрываются
  стрелкой с адресом («→ Аппаратная · MIX-01»).
- Кабели между помещениями выделены; в кабельном журнале — помещения начала и
  конца кабеля, спецификация — с колонкой «Помещение».
- Подсказка симуляции: HDMI/USB между помещениями длиннее допустимого —
  «используйте HDBaseT или AV-over-IP».

## 2. Чертежи по ГОСТ СПДС — сделано (PDF, SVG, DXF, VSDX), черновые до проверки специалистом

Чертёж строится из модели схемы (вектор), а не из снимка экрана.

- Виды схем (терминология ГОСТ 2.701, оформление по СПДС):
  - **структурная** — устройства-блоки с позиционными обозначениями, одна
    линия связи на пару устройств, помещения рамками;
  - **функциональная** — тракты по видам сигнала (звук, видео, сеть/управление);
  - **схема соединений** — разъёмы и маркировка кабелей + кабельный журнал и
    перечень оборудования.
- Оформление (сделано): форматы А4–А1 (ГОСТ 2.301), рамка, основная надпись
  формы 3 по ГОСТ Р 21.101-2020 на всех листах, многолистовость и нумерация
  листов; поля штампа (шифр, наименование объекта, стадия, должности и
  фамилии) — в настройках проекта. Шрифт — PT Sans Narrow (открытая лицензия)
  вместо шрифта типа А/Б по ГОСТ 2.304.
- Не сделано: формы 5 и 6 для листов текстовых документов (спецификация,
  кабельный журнал сейчас — с формой 3), шрифт по ГОСТ 2.304; размеры граф
  штампа не сверены с текстом стандарта.
- Проверка: DXF разобран ezdxf, VSDX — libvisio и LibreOffice Draw; в
  AutoCAD, nanoCAD и Visio не открывались. До проверки представительных
  листов специалистом по оформлению (кириллица, длинные наименования,
  многостраничные таблицы, разные форматы, шкафы) чертежи — черновые.
- Форматы выпуска из одной модели листа: **PDF** (векторный, многолистовой),
  **SVG** (лист — файл, комплект — ZIP), **DXF** R12 (AutoCAD, nanoCAD,
  LibreCAD; слои по толщине линий), **VSDX** (Visio, LibreOffice Draw).

## 3. Учебный режим — сделано (17 заданий, редактор заданий преподавателя)

- Задания в JSON (проверяются схемой): цель, стартовая схема, доступное
  оборудование, критерии автопроверки на основе симуляции («звук доходит до
  обеих АС в норме», «нет ошибок», «видео на дисплее через HDBaseT» — по
  тракту сигнала, а не по наличию устройства на холсте).
- Типы: «собери систему» и «найди и исправь неисправность» (кнопка
  «Исправить» скрыта, есть пошаговые подсказки).
- Прогресс хранится в браузере; первый набор — 8–10 заданий от простого к
  сложному.
- Редактор заданий: задание из схемы на холсте, проверки по симуляции
  эталона, обмен файлом JSON.
- **Позже:** учётные записи учеников и общая статистика — вместе с хранением
  на сервере.

## 4. Каталог оборудования

Сверка характеристик с документацией производителя и конкретные модели
вместо типовых — когда будут доступны источники: разрешённые домены
производителей в сетевых настройках окружения или выгрузка (модель, порты,
характеристики, ссылка на страницу производителя), которую можно проверить и
импортировать с полем `source`. Первыми — 21 модель производителей из заданий
и примеров (список — `docs/STATUS.md`): порты, правила коммутации, питание
(+48 В, PoE), высота в юнитах. В интерфейсе и спецификации уже видно, какие
данные сверены, какие ориентировочные, какие устройства типовые.
